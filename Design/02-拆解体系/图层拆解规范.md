# 图层拆解规范

> 本文定义小角的五层正交模型——所有表情、装饰、配色都以它为坐标系。生成器的渲染顺序、数据结构、命名约定全部由此派生。

## 五层正交模型

一个小角 = **场景层 × 基板层 × 表情层 × 装饰层 × 色彩映射**。

前四层是 z 轴上的叠加图层（自底向上），色彩映射不是图层，而是**渲染时作用于各层填充色的令牌映射**（见 [色彩规范](../05-色彩系统/色彩规范.md)）。

| 层 | z 序（底→顶） | 职责 | 数据来源 |
| --- | --- | --- | --- |
| 场景层 scene | 0（可选） | 背景色块、背景形状、小场景道具 | 场景库（第一版可只有「透明」与「纯色」） |
| 基板层 base | 1 | 接触阴影、软阴影、身体、右下切角——小角的本体，**恒定不变** | 由 `geometry.json` 纯代码直绘 |
| 表情层 expression | 2 | 双眼（或其替代形态）——情绪的唯一载体 | 表情库（[表情库清单](../03-表情模块/表情库清单.md)） |
| 装饰层 decoration | 3 | 帽子、眼镜、道具等一切外挂元素 | 装饰库（[装饰库规划](../04-装饰模块/装饰库规划.md)） |

正交性规则（生成器必须保证）：

1. 换表情不改变画布、基板、装饰；换装饰不改变表情；各层互不感知；
2. 基板层在所有产物中**逐字节一致**（阴影、身体、切角），它是「同一只小角」的判据；
3. 装饰层恒在表情层之上（墨镜要盖住眼睛）；若未来出现需要垫在身体之下的装饰（如围巾绕后），以装饰元数据的 `z_offset` 显式声明；
4. 色彩映射只改「可换令牌」的填充，**永远不触碰**：深墨 `#222222`（眼睛/笔画）、砖红 `#D44A36`（切角）、阴影参数。

## 与现有表情 SVG 的结构对齐（实测）

`小角IP/04-表情包/SVG/*.svg` 已经是这套模型的雏形，以 `sticker-02-happy.svg` 为例：

```xml
<svg viewBox="0 0 780 560">                     <!-- 贴纸画布 780×560 -->
  <defs>…soft-shadow / contact-shadow 滤镜…</defs>
  <g transform="translate(90 90)">              <!-- 身体原点平移至 (90,90)，四周留 90 -->
    <rect …/>                                   <!-- 软阴影层 -->
    <rect …/>                                   <!-- 接触阴影层 -->
    <path d="M95 0H505A95…Z" fill="#F3EBDF"/>   <!-- 身体 -->
    <path d="M410 380H505A95…V190Z" fill="#D44A36"/> <!-- 切角 -->
    <g transform="…">…</g>                      <!-- 左眼表情（独立组，含 ~1.154 缩放补偿） -->
    <g transform="…">…</g>                      <!-- 右眼表情（独立组） -->
  </g>
</svg>
```

拆解动作 = 把最后两个表情 `<g>` 换成任意表情片段、在其上插入装饰 `<g>`。基板四层（两阴影 + 身体 + 切角）就是可直接复用的基板层实现。

## 生成器输入数据格式

一份组合配置（compose config）描述一次渲染：

```json
{
  "canvas": "sticker-780x560",
  "scene": null,
  "expression": "expr-02-happy",
  "decorations": [
    { "id": "deco-hat-beanie",  "anchor": "head-top" },
    { "id": "deco-glasses-round", "anchor": "eyes" }
  ],
  "palette": "skin-original"
}
```

约定：

- `expression` 必填，恰好一个；`decorations` 为数组，同一挂点只能挂一个装饰（互斥规则见 [装饰库规划](../04-装饰模块/装饰库规划.md)）；
- 装饰数组顺序即渲染顺序（后渲染者在上）；元数据中另有 `z_offset` 微调；
- 该 JSON 即生成器的唯一输入，CLI 批量模式复用同一格式。

## 命名约定

| 对象 | 约定 | 示例 |
| --- | --- | --- |
| 表情资产 | `expr-{两位编号}-{英文名}` | `expr-03-wink` |
| 装饰资产 | `deco-{品类}-{名称}` | `deco-hat-beanie`、`deco-glasses-round` |
| 皮肤 | `skin-{名称}` | `skin-original` |
| SVG 图层 id | 与资产 id 一致 | `<g id="deco-hat-beanie">` |
| 组合配置 | kebab-case 键名 | 见上例 |

现有素材的 12 个表情沿用原编号映射到 `expr-01` … `expr-12`（对应表见 [表情库清单](../03-表情模块/表情库清单.md)）。

## 产物形态

生成器每次渲染产出一个 SVG 文档，图层结构固定为：

```
svg[viewBox=780 560]
└─ g#canvas-root [translate(90 90)]
   ├─ (场景层，若有)
   ├─ g#base        阴影×2 + 身体 + 切角
   ├─ g#expression  表情片段内嵌（1–2 个子组）
   └─ g#decorations 各装饰片段按序内嵌
```

导出 PNG 由该 SVG 栅格化而来（方案见 [生成器需求规格](../06-生成器设计/生成器需求规格.md)），保证 SVG 与 PNG 逐像素同源。
