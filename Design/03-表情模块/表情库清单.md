# 表情库清单

> 表情层是小角唯一的情绪载体。本文梳理素材 12 个表情与原创 10 个表情（共 22 个），定义表情片段的提取与新增规范。

## 表情的本质

表情 = 双眼图层的替换。约束（继承自 [小角设定总纲](../01-IP设定/小角设定总纲.md)）：

- 颜色恒为深墨 `#222222`，不参与换肤；
- 笔画宽 17、圆端圆角（`stroke-linecap/linejoin: round`）；闭合形状（豆眼、爱心眼）为纯色填充；
- 无嘴、无眉、无眼白——情绪只靠两只眼睛的形状。

### 决策点：10-酷 的归属（可讨论）

墨镜本质是**覆盖眼部的装饰**。建议拆解为：表情 `expr-10-cool` 只保留墨镜遮盖后的眼部形态（或不做该表情），墨镜独立为装饰 `deco-glasses-sunglasses`，挂在 `eyes` 挂点。这样「墨镜 + 任意表情」成为合法组合，内容量更大。原 10-酷成品照常保留在素材库。

## 表情片段 SVG 规范

从贴纸 SVG 中提取的表情片段（实测结构，以 `expr-02-happy` 为例）：

```xml
<!-- expressions/expr-02-happy.svg —— 身体坐标系片段 -->
<g id="expr-02-happy">
  <!-- 每只眼睛一个子组；子组自带平移 + ~1.154 缩放补偿，提取时原样保留 -->
  <g transform="translate(168 190) scale(1.1538 1.1504) translate(-168 -190)">
    <path d="M136 201Q168 135 200 201" fill="none"
          stroke="#222222" stroke-width="17"
          stroke-linecap="round" stroke-linejoin="round"/>
  </g>
  <g transform="translate(306 190) scale(1.1538 1.1504) translate(-306 -190)">
    <path d="M274 201Q306 135 338 201" fill="none" stroke="#222222" …/>
  </g>
</g>
```

- 片段使用**身体坐标系**（不含贴纸画布的 translate(90 90)），由生成器统一放置；
- 每个片段配一条元数据（expressions.json）：

```json
{
  "id": "expr-02-happy",
  "name": "开心",
  "no": 2,
  "covers_eyes": false,
  "source": "小角IP/04-表情包/SVG/sticker-02-happy.svg"
}
```

## 提取方案（一次性脚本，建议放 `Design/03-表情模块/extract_expressions.py`）

1. 遍历 `小角IP/04-表情包/SVG/sticker-*.svg`；
2. 剥离 `<defs>` 滤镜、两层阴影 rect、身体 path、切角 path（这些属于基板层，逐字节一致，可交叉校验脚本正确性）；
3. 保留剩余的表情 `<g>` 子组，按上表映射写入 `expr-{no}-{name}.svg`；
4. 输出 `expressions.json` 索引 + 一份「提取报告」（每个源文件剥掉了什么、留下了什么）；
5. 校验：把片段 + 代码直绘基板重新合成，与源 SVG 做像素 diff，应为零差异（这是整个拆解体系可信度的基石）。

## 原创表情扩展（v0.4，10 个，机制互不重复）

设计方法：先盘点素材 12 表情已用的「眼睛机制」（**全尺寸验证是硬要求**：小瓦片成立不代表全尺寸成立，v0.4 窃喜初版即在此翻车）（豆眼、上弧、折线、圆点、爱心、墨镜、螺旋、泪滴、斜切、横杆），新表情只探索**尚未使用的机制**，避免同质化。全部遵守既有语言：17 宽圆端笔画、无嘴无眉无眼白、情绪只在眼睛；辅助元素使用专用令牌（v0.5）：腮红 `{{blush}}`、汗滴/盈泪 `{{fluid}}`，不绑 corner/accent——避免换肤后色相翻车。

## 扩展方向（下一批候选）

剩余未用的机制：瞳位偏移（豆眼内再做偏移需要拆分瞳孔——破坏"纯色块眼"语言，慎用）、双眼不同大小、眼睑半遮（斜切直线+豆眼下半）、组合道具（思考气泡、音符）。候选：左右不对称大小（懵）、眼睑半遮（鄙视）、双语悸动？——下一批先做：懵（大小眼）、鄙视（半遮）、傲娇（斜移+侧目组合）。
